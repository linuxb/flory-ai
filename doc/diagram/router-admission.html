Router: Interposition, Template Binding, and Sub-DAG Admission

How a rule-governed transition is taken without a model call. Companion to Doc 10 — Deterministic Routers and Rule Templates; check-rules R12–R14 live in Doc 02 §3.4.

A. Mandatory interposition (R14)

A planner never writes router syntax. When its proposal wires a tool caller straight into a planner, the engine normalizes the graph. Topology is therefore identical whether or not a rule is bound — attaching a rule changes a pin, never a shape.

B. Template binding resolves out of band

Binding never passes through a model. An explicitly declared router resolves its pinned contract by URI and digest; an auto-interposed router resolves through a stable topological coordinate. A slot with nothing registered is a transparent pass-through, not an error.

C. Three lines of defence

The hazard a deterministic rule creates is late detection — an invalid branch found after an irreversible pivot has passed, when the proposing planner has already fallen below the backtrack floor. Detection therefore moves left, to publish time and freeze time.

D. Runtime evaluation and sub-DAG admission

A router is evaluated by the Engine synchronously on parent completion. It is never queued — a vertex that performs no call has nothing for a worker to claim, and a queue row would let a lease expiry fabricate a failure for a pure function.

E. Derived placement and R12

A router has no side effects and is never a scope member, so its transaction placement is computed from the ancestor graph — never declared, never inferred at runtime. Flory defines no runtime scope-merge protocol: atomicity across parallel branches is declared at freeze time or it does not exist.
